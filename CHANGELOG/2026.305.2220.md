# 2026.305.2220 — fix(params): restore the projection to the canonical cue@v0.16.1 output

## Summary

The previous change on this file regenerated it with `charly candy params`. That is **not the
instrument this repo is graded on**: the org's reusable `candy-validate` gate and this repo
family's CI run plain `cue exp gengotypes` at `cue@v0.16.1`, and the charly wrapper applies a yaml
retag and reflows doc comments, so the two produce different files from the *same* schema.

Measured with the canonical instrument against `main` after that change landed:

```
$ # splice the package clause onto candy/plugin-feature/schema/*.cue, then
$ cue@v0.16.1 exp gengotypes . && diff <generated> candy/plugin-feature/params/cue_types_gen.go
4 diff lines   → FAIL
```

The org already recorded this class in `opencharly/.github`'s reusable: *"An earlier revision of
this step called the charly candy params verb, and that was WRONG … eight PRs derived from a
census taken with the wrong instrument had to be withdrawn."* This is one of those eight, corrected
in place.

The fix restores the file to exactly what `cue@v0.16.1` emits.

### The removed tags are PROVEN inert (no runtime effect)

Removing `yaml:"…"` tags would be a runtime-observable change **if** anything YAML-decoded these
structs. Nothing does. A plugin never receives YAML: charly hands it JSON, and every plugin decodes
that JSON into its params struct.

```
$ git -C plugin-feature show origin/main:candy/plugin-feature/provider.go | sed -n '34,42p'
	var op spec.Op
	if len(req.GetParamsJson()) > 0 {
		if err := json.Unmarshal(req.GetParamsJson(), &op); err != nil {
			return sdk.ResultJSON("fail", "feature: decode op: "+err.Error())
		}
	}
	var in params.FeatureInput
	kit.DecodeInput(op.PluginInput, &in)
```

`kit.DecodeInput` goes through JSON as well, so the json tags are the only ones on the path:

```
$ git -C sdk show origin/main:kit/kit.go | sed -n '116,122p'
func DecodeInput(in map[string]any, out any) {
	if len(in) == 0 {
		return
	}
	b, err := json.Marshal(in)
```

And no YAML decoder touches a params struct anywhere in the org — the sdk's four `yaml.Unmarshal`
sites decode the install ledger, system info and generic YAML documents, not plugin params:

```
$ for r in plugin-feature charly sdk; do git -C $r grep -c 'yaml.Unmarshal' origin/main -- '*provider.go' 'kit/*.go'; done
plugin-feature/*provider.go: 0      charly/*provider.go: 0
sdk/kit/install_ledger.go, sdk/kit/system_info.go, sdk/kit/yaml.go  (none decodes a params struct)
```

So the tag removal changes no decoded key on any path that exists: the same YAML config produces
the same CUE value, and the same JSON reaches the plugin.
